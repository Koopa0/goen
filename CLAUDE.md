# goen

A Traditional-Chinese 3C storefront: Go, server-rendered `templ`, PostgreSQL,
Stripe. This file records what is specific to this repository. General Go and
web correctness lives in `~/go-spec`; where the two disagree about goen, this
file wins.

go-spec is not a reference goen reads at a distance — the parts that apply are
imported and in force:

| What | Where | Adapted |
|---|---|---|
| Linter configuration | `.golangci.yml` | `run.build-tags: [integration]`; the sqlc exclusion narrowed to the three generated files; `hugeParam` raised to 192 |
| Go and web rules | `.claude/rules/` (15 of 22) | Verbatim. The seven left behind are Genkit, NATS, Ristretto and gRPC material goen has no use for |
| Write-time guards | `.claude/hooks/` (6 of 19) | `check-generated-code.sh` narrowed so it does not block goen's hand-written tests in `internal/db`, and extended to `*_templ.go` and the vendored CSS |
| Permissions | `.claude/settings.json` | goen's toolchain; `.env` and key material denied |

## Orientation (30 seconds)

One Go binary serves the storefront, the customer account, and `/admin`. Pages
are HTML the server renders. htmx swaps fragments; it never owns a write. The
database is PostgreSQL and the binary refuses to start without it.

## Stack

- Go 1.26.5 · `net/http` routing, no framework
- `templ` v0.3.1020 — generated `*_templ.go` is committed and never hand-edited
- PostgreSQL via `pgx/v5` + `pgxpool`; queries generated by `sqlc` v1.31.1 into
  `internal/db`, which is never hand-edited
- Migrations: `golang-migrate`, `migrations/NNN_name.{up,down}.sql`
- CSS: the koopa.dev design system, vendored verbatim under `assets/css/ds/`.
  Plain CSS with `oklch` tokens — there is no Tailwind and no CSS build step.
- htmx 2.0.10, vendored at `assets/js/vendor/htmx.min.js`
- Tests: stdlib + `go-cmp`. No testify, no mock framework.
- `golangci-lint` v2.12.2, zero tolerated findings

## Layout

```
cmd/goen/          entry point and wiring only — routes, middleware, config
assets/            embedded static files + the versioned asset handler
  css/ds/          the design system, vendored; edit upstream, not here
  css/app/         page composition and responsive behaviour — ours
internal/
  <feature>/       feature.go, handler.go, store.go, query.sql, *_test.go
  db/              sqlc output — never edited by hand
  ui/layouts/      document shell, header, footer
  ui/pages/        page bodies and their view models
  ui/icons/        inline SVG, depends on nothing
migrations/        numbered SQL
```

Package by feature. There is no `services/`, `repositories/`, `handlers/`, or
`models/` directory, and no domain/infrastructure/application layering.

## Project pins (the decisions `native-web-first` asks each repo to make)

### Write-face rule

**Every mutation is a plain `<form method="post">` that works with scripting
off.** The handler validates, writes, and answers `303 See Other` so a reload
cannot resubmit. A rejected form re-renders at `422` with the submitted values
intact and `aria-invalid` on each control it refused.

`hx-*` attributes may only change *what is written back* — a fragment instead
of a page. They may never become the only way a write happens. The test for any
new form: turn JavaScript off; if the action stops working, it is not done.

Server-side validation is the authority. `required`, `type=email`, `minlength`
and friends are the first line, never the only one.

### UI source of truth

1. The Claude Design project `8c5aa51d-39a5-4799-939f-346be183be84` is where the
   visual language is decided. Its `.dc.html` files are **input to convert, not
   source to paste**: re-derive the semantics, drop the canvas runtime
   (`x-dc`, `dc-import`, `sc-if`), and never carry its inline styles across.
2. `assets/css/ds/` is that project's design system, vendored verbatim. Fix it
   upstream and re-vendor; do not patch it locally.
3. Everything the design system does not own — page composition, the responsive
   rules that fold the 1440 and 375 artboards into one document — belongs in
   `assets/css/app/app.css` as real classes.

**Do not introduce** another client framework, another CSS framework, a
component library with a runtime, or a second icon system. htmx is the one
admitted client dependency and it was an explicit human decision, not an
implementation one. Adding to this list is also a human decision.

### State mechanism

`data-*` attributes are the only contract between HTML and JavaScript, and the
server renders them. `assets/js/goen.js` is the one enhancement file: no build
step, no modules, no framework. Every behaviour in it no-ops when its element
is absent, and the site is fully usable with the file deleted.

Persisted UI state, when goen grows any, is a cookie the server reads and
stamps onto `<html>` so the correct state paints on the first byte.

### Renderer boundary

`assets/css/ds/` is vendored, not authored here. When something looks wrong,
style the classes it already defines from `app.css`; do not reshape markup to
work around it, and do not fork a design-system rule into the app layer.

### Chrome language

All functional text — labels, buttons, validation messages, `aria-label`s,
empty states, error pages — is Traditional Chinese. Code, identifiers,
comments, log messages, and commits are English. The locale switch in the
header and footer renders, but i18n is not implemented: the English option
carries `aria-disabled` rather than pretending to work.

## Predictable mistakes here

1. **Pasting the design file's inline styles into templ.** They cannot express
   a media query, which is the whole job — the artboards are two fixed widths
   and the product is one responsive document. Convert them to classes in
   `app.css`.
2. **Reaching for a class the design system does not define.** Check
   `assets/css/ds/` first; `ui-*` is theirs, `goen-*` is ours. Inventing a
   second `.btn` is how two visual languages start.
3. **Letting htmx own a write.** See the write-face rule. `hx-post` on a form
   with no `action` is the failure.
4. **Trusting a screenshot for layout.** Chrome cannot open a window under
   ~500px on macOS, so `--window-size=375` renders at 500 and crops: overflow
   it shows is fake and overflow it hides is missed. Drive
   `Emulation.setDeviceMetricsOverride` and measure boxes.
5. **Reporting a gate green from a piped command.** `go build ./... | head`
   exits 0 whatever the compiler said. Use `cmd && echo PASS || echo FAIL`, and
   `make verify && git commit`, never `;`.
6. **A test nobody has watched fail.** Mutate the behaviour, prove the mutation
   applied, and require red before calling a test a lock.
7. **A suite that reports coverage it does not have.** The first schema suite
   showed 48 green subtests; deleting constraints one at a time proved 48 of
   the 65 CHECKs could be removed without a single failure. Enumerate what must
   be covered from `pg_constraint` / `pg_index` / `pg_trigger` and fail on
   anything missing — never from a hand-written list.
8. **Asserting that an error happened rather than which one.** A statement
   meant to prove a CHECK often trips a unique index first. Bind the assertion
   to `PgError.ConstraintName`.
9. **A concurrency test with two goroutines and a start channel.** They finish
   microseconds apart and never overlap; every guard here stayed green with its
   lock removed. Hold T1's transaction open while T2 runs.
10. **Parameterising `status = $1` against a partial index.** The planner
    cannot prove the parameter is always `'active'`, so
    `products_category_published_idx` goes unused. Write the literal.
11. **An interface introduced so a test can substitute something.**
    `interfaces.md` is explicit that tests are never a reason. goen had two,
    each with a hand-written fake of the database behind it, and the fake
    enforced none of the constraints the real write meets. The tests are
    integration tests now.
12. **A gate that repairs what it is checking.** `sqlc-check` regenerated over
    `internal/db` and then diffed, so it reported a stale tree once and passed
    on the retry. `go test -run='^$$'` still runs `TestMain`, which starts a
    container — that is not a compile check.
13. **Two invocations of one generator.** `templ generate` from the repository
    root and `templ generate -path internal/ui` write different `FileName`
    strings, so `make verify` passed and then failed on the output of its own
    previous run. Run a gate twice before believing it.

## Build tools stay out of go.mod

`templ` is a `tool` directive because it generates code this module compiles.
Everything else — `golangci-lint`, `sqlc`, `squawk`, `ko`, `migrate` — is
version-pinned in the Makefile and invoked from outside the module.

The rule came from measuring: adding `ko` as a `tool` took the module graph
from 104 modules to 528, because ko carries the AWS, Azure, GCP and Kubernetes
clients it needs for registry authentication. None of it reaches the binary,
and all of it would sit inside every `govulncheck`, Trivy and Dependabot run
against this repository from then on. `go run pkg@version` pins the version
just as firmly without joining the graph.

Before adding a `tool` directive, run `go list -m all | wc -l` before and
after. If the tool does not generate code this module compiles, it does not
belong there.

## The database enforces what it can

goen's data rules live in the schema, not only in Go: 130 CHECKs, 58 foreign
keys, 43 unique indexes and 17 rule triggers. Application code is where rules
go to be forgotten — a second write path appears, a retry runs a step twice —
so anything that would corrupt money, stock or history is refused by
PostgreSQL, where there is no second path.

Rules that span rows are triggers rather than CHECKs, and each locks its
aggregate root before it reads: `refunds_within_capture` takes the payment row
`FOR UPDATE`, `store_credit_never_negative` takes the account row. Without the
lock, two concurrent writers each pass a test the other is about to invalidate.
Each raises with an explicit `CONSTRAINT` name so a caller — and a test — can
say which rule refused.

`make test-integration` runs the conformance suite against a real PostgreSQL
through testcontainers. It derives what must be covered from the system
catalog, so adding a constraint without a case fails the build. `make verify`
does not run it (it needs Docker); run both before calling schema work done.

## Commands

| Command | What it does |
|---|---|
| `make db-up` | Start PostgreSQL in Docker on 127.0.0.1:5433 |
| `make migrate-up` | Apply migrations |
| `make run` | Generate templ, then serve on 127.0.0.1:9700 |
| `make test` / `make test-race` | Tests |
| `make sqlc` / `make sqlc-check` | Regenerate / verify `internal/db` |
| `make lint` / `make fmt` / `make fmt-check` | golangci-lint v2 and formatting |
| `make verify` | The gate, no Docker: fmt-check → templ-check → squawk → sqlc-check → vet → lint → integration-build-check → test-race |
| `make verify-all` | `verify` plus `test-integration` and `vuln` |
| `make test-integration` | The schema conformance suite (needs Docker) |
| `make vuln` | govulncheck over the paths the binary actually reaches |
| `make image` / `make image-push` | ko build; base image pinned by digest |

Configuration is environment-only; `.env` is read by the Makefile in
development. `GOEN_DATABASE_URL` is required and has no default — a missing one
must stop the binary rather than quietly reach some other database.

## Delivery state

Batch ⑧ (關於我們 / 聯絡我們) is implemented. Batches ① home, ② listing +
search, ③ PDP, ④ cart + checkout, ⑤ auth, ⑥ account, ⑦ admin are not. Routes
the chrome already links to — `/c/*`, `/cart`, `/account`, `/search`, `/deals`
and the remaining policy pages — resolve to the not-found page on purpose.

Known follow-ups, none of them blocking this batch:

- Fonts load from Google Fonts (one `@import` inside the vendored design system
  plus a Noto Sans TC `<link>`). Self-host and subset before production; the CSP
  in `cmd/goen/server.go` drops two third-party origins when that happens.
- Stripe is not wired; it arrives with checkout in batch ④.
- The storefront read model (min price, rating, "綜合推薦" rank) is not built.
  Aggregating those per page view will not hold; a projection is the likely
  answer, but the decision waits for a measurement rather than a guess.
- Facet filtering must match all selected values against ONE variant. Matching
  them across a product's variants would show "blue, in stock" for a product
  whose blue is sold out and whose black is not.
