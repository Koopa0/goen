# Prompt for Claude Design — goen 的三件 UI/UX 工作

貼給 Claude Design。這份是**完整的**,不需要再問我背景。

---

## 這是什麼專案

**goen(緣)** 是一間繁體中文的台灣 3C 選品電商,已經是可以運作的完整網站:
89 條路由、商店前台 + 會員中心 + 後台,金流走 Stripe,資料庫是 PostgreSQL。

## 你必須先知道的三條規則(這些不能改)

1. **視覺語言是 koopa.dev design system**,vendored 在 `assets/css/ds/`,
   `ui-*` 前綴,oklch 色彩 token,**沒有 Tailwind、沒有 build step**。
   頁面組合用 `goen-*` 前綴寫在 `assets/css/app/app.css`。
   別引入第二套 CSS 框架、第二套圖示系統、或任何帶 runtime 的元件庫。

2. **每一個寫入動作都是 `<form method="post">`,關掉 JavaScript 也要能動。**
   htmx 只能改變「回寫什麼」,不能成為寫入發生的唯一途徑。
   任何設計如果需要 JS 才能送出,就是不能採用的設計。

3. **色票**(暖調中性,不是純黑白):
   ```
   --bg:            oklch(0.966 0.005 106)   暖白底
   --panel:         oklch(0.988 0.003 106)   面板
   --fg:            oklch(0.22  0.012 107)   主文字
   --fg-muted:      oklch(0.40  0.020 107)
   --fg-subtle:     oklch(0.53  0.022 107)
   --border:        oklch(0.88  0.008 106)
   --border-strong: oklch(0.80  0.010 106)
   ```
   斷點:375(手機)、768(平板)、1024、1440(桌機)。
   觸控目標最小 44px。

## 工作一(最優先):全站促銷公告條

### 為什麼卡住

資料庫裡有 `promo_banners` 這張表,欄位齊全(訊息、窄螢幕用的另一段短文案、
折扣碼、CTA 標籤與連結、起訖時間、啟用開關),但**版面上沒有它的位置**。
我不會自己發明一個橫跨全站的視覺元素 —— 那是設計決定。

### 你要決定的

1. **位置**:在 header 之上?之內?還是首頁專屬?
   - 若在 header 之上,捲動時跟著走還是固定?
   - 它會出現在**每一頁**(包含結帳、會員中心、後台)還是只有商店前台?
2. **窄螢幕**:375px 只有一行文字的高度。短文案怎麼呈現?CTA 還放得下嗎?
3. **關閉**:能不能關?如果能,關掉之後多久回來?
   (注意:記住「已關閉」是一次寫入,依規則 2 要嘛是 form,
   要嘛就是純 CSS 的 `<details>` 之類不需要記住狀態的做法。
   若你要「記住」,我這邊會用 cookie + 伺服器端渲染,不用 localStorage。)
4. **含折扣碼時**:`code` 欄位有值時要不要顯示成可複製的樣子?
   複製到剪貼簿需要 JS —— 依規則 2,它只能是「錦上添花」,
   純文字本身就要能被選取。

### 交付

375 和 1440 兩個 artboard,包含:有 CTA / 無 CTA、有折扣碼 / 無折扣碼
四種組合。加上它與 header 疊在一起時的完整頁首。

## 工作二:兩階段驗證的三個畫面

### 背景

後台可以退款、發放商店額度、調整庫存,所以現在進後台要輸入 TOTP 六位數驗證碼
(Google Authenticator 那種)。功能已經做完並且測過了,
但畫面是我用現有的 `ui-field` / `ui-input` 拼的,設計系統裡沒有這個 pattern。

### 三個狀態

**A. 還沒設定** — 一句說明 + 一個「開始設定」按鈕。

**B. 設定中(關鍵畫面)** — 顯示一組 32 字元的 base32 祕密字串,
**只會顯示這一次**。使用者要把它手動輸入進手機上的驗證器 app。
- 我目前把它拆成 4 個字元一組(`YGGP JPIE ...`),因為連續 32 個字元
  一邊看一邊打會跳行
- 下面還有一個 `otpauth://` 開頭的長 URI,收在 `<details>` 裡
- **我不會畫 QR code** —— 那要多一個依賴。如果你認為沒有 QR code
  這個流程不可用,告訴我,那會是一個值得付的依賴,但要你先說服我
- 然後是「輸入驗證器上目前的六位數字」的欄位 + 確認按鈕

**C. 每次進後台** — 只有一個六位數字欄位 + 送出。
下面一行小字:驗證器不見了怎麼辦(答案是請另一位管理員移除設定)。

### 你要解決的

1. **六位數字的輸入框**。單一欄位(我現在的做法)還是六個獨立格子?
   六個格子在沒有 JS 的情況下**不能自動跳格**,依規則 2 那就是壞掉的設計 ——
   除非你設計成「六格但每格都要手動點」,那體驗更差。
   所以我傾向單一欄位,但要你確認排版:字距、寬度、字級。
2. **祕密字串的呈現**。等寬字?分組間距?怎麼讓「只會顯示一次」這件事
   看起來夠嚴肅但不嚇人?
3. **錯誤狀態**。驗證碼錯誤、驗證碼已經用過、被節流(429)三種。
   訊息本身我寫好了,要的是它們出現的位置與樣式。

### 交付

375 和 1440,三個狀態各一,加上錯誤狀態。

## 工作三:後台的視覺語言檢查

### 背景

後台已經長到九個區塊:商品、庫存、訂單、退貨、商店額度、折扣碼、
限時活動、首頁主視覺、操作紀錄。我一路都用商店前台的設計系統拼出來,
沒有為後台做過整體設計。

### 具體的問題

1. **列表密度**。商店前台的間距是為「瀏覽」設計的(寬鬆、有呼吸感),
   後台是為「掃描找一列」設計的。現在後台用同一組間距,一頁看不到幾筆。
   要不要有一組更緊的後台間距?
2. **表單佈局**。後台的表單多半是「左邊表單、右邊列表」的兩欄
   (`goen-admin__productlayout`)。1440 下比例對嗎?768 怎麼折?
3. **狀態標記**。訂單狀態、折扣碼啟用/停用/不在檔期、活動進行中、
   商品草稿/上架/封存 —— 現在都用 `ui-badge`,顏色沒有系統。
   要不要一組後台專用的狀態色?
4. **操作紀錄頁**。這是一個時間序列,每列有:動作、操作者、時間、
   before/after 的 JSON、request id。金錢/庫存相關的列我加了左邊框標記。
   這種「密集、可掃描、偶爾要展開細節」的列表值得單獨設計。
5. **導覽**。九個項目現在是一排水平連結,1440 剛好塞得下,768 會擠。

### 交付

不需要重畫全部九頁。我要的是:
- 一組後台的間距與密度規範
- 狀態標記的色彩系統
- 導覽在 768 的解法
- 挑**一頁**(建議是操作紀錄,因為它最密集)做完整的 375/768/1440

## 交付格式

跟以前一樣:`.dc.html`。我會把它當成**要轉換的輸入,不是要貼的原始碼** ——
重新推導語意、丟掉 canvas runtime(`x-dc`、`dc-import`、`sc-if`)、
inline style 一律不帶過來。所以請把設計意圖寫在註解裡,
特別是「為什麼這樣排」而不只是「排成這樣」。

有任何一項你覺得規則 1 或規則 2 讓設計變得不合理,直接說 ——
那是值得討論的,比繞過去好。
