# Storefront visual approach and batch ① handoff

This is the anchor for continuing the storefront's visual work in a fresh
session. Read it, then `CLAUDE.md`, then `git log --oneline -15`. The repository
is the source of truth; this file just points at what matters.

## The design approach (a decision, not a default)

goen's visual language stays the **koopa.dev design system** — vendored under
`assets/css/ds/` (the `ui-*` classes) with `oklch` tokens, no Tailwind, no build
step. This was reaffirmed deliberately: CLAUDE.md makes "no Tailwind" a human
decision, and it is not being reversed.

The owner provided **Tailwind UI v4** libraries as *reference*, not as a
framework to adopt:

- `~/Downloads/ecommerce-v4/html/` — `page-examples/` (storefront, category,
  product, cart, checkout, order pages) and `components/` (category filters,
  product lists, reviews, cart, store nav). Directly maps to goen's batches.
- `~/Downloads/marketing-v4/html/sections/` — heroes, footers, newsletter,
  feature/CTA sections.
- `~/Downloads/application-ui-v4/html/` — forms, overlays, navigation, etc.

Use them exactly as CLAUDE.md already says to use the Claude Design `.dc.html`
files: **input to convert, not source to paste.** Take the information
architecture, section composition, responsive breakpoints, and accessibility
semantics (landmarks, `aria-*`, focus order); re-derive them into goen's classes.
Never carry a Tailwind utility class or an inline style across. `ui-*` is the
design system's; `goen-*` is ours (page composition in
`assets/css/app/app.css`). The visual source of truth remains the Claude Design
project `8c5aa51d-39a5-4799-939f-346be183be84`.

## Batch ① home — state

Done and on `main` (see `git log`):

- **Dev catalogue seed** — `make db-seed` loads `seed/dev_catalog.sql` (15
  products, generated by `seed/gen_seed.py`).
- **Read model** — measured; per-view aggregation for now, projection when the
  catalogue passes ~1–2k active products (`docs/decisions/001-home-read-model.md`).
- **Feature package + route** — `internal/home/` (query.sql, store, handler) and
  `pages.HomeView`/`pages.HomeTile` in `internal/ui/pages/home.go`. `GET /` now
  renders live data through `home.Handler`. An integration test loads the seed.

The home page is **functional but unstyled**: `internal/ui/pages/home.templ`
uses `goen-hero`, `goen-cat`, `goen-tile`, `goen-section__title` — classes that
have **no CSS yet**. That is the remaining work.

To see it: `make db-up && make migrate-up && make db-seed && make run`, then open
`http://127.0.0.1:9700/`.

## What's left (the visual batch)

1. **Pull the home design** — the Claude Design `.dc.html` home + the Tailwind UI
   `storefront-pages` examples. Derive the section inventory (hero, category
   tiles, recommended grid, and whatever else the design shows).
2. **`home.templ` + `app.css`** — style the existing `goen-*` classes (and add
   what the design needs) in `assets/css/app/app.css`. Fold the 1440 and 375
   artboards into one responsive document. Product imagery is a placeholder
   until a media pipeline exists — design the tile to work with and without an
   image (`HomeTile.HasImage()`).
3. **Test and ship** — `make verify-all` green; verify layout by driving
   `Emulation.setDeviceMetricsOverride` and **measuring boxes**, not by trusting
   a cropped screenshot (CLAUDE.md predictable mistake #4). Commit with a clean
   author (no AI attribution — the owner's standing preference).

## Non-negotiables (from CLAUDE.md)

- Every write is a plain `<form>` that works with scripting off; htmx (now 4.0)
  only changes what is written back. The home is read-only, so this mostly means
  links, not forms.
- Do not reach for a class `assets/css/ds/` does not define; do not fork a
  design-system rule into the app layer; fix the design system upstream and
  re-vendor instead.
- Commits end with no `Co-Authored-By` / Anthropic trailer; the author is the
  owner. Keep `CLAUDE.md` the filename it is.
