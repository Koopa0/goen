# Demo deployment evidence

[goen.koopa0.dev](https://goen.koopa0.dev) is a public read-only demo of the
fifteen-product sample catalogue. The root README names three visitor-facing
limits; this directory holds the sanitized configuration and scheduled restore
job a reviewer can read without host access.

## What the README promises

| Assurance | Mechanism in this revision |
| --- | --- |
| Payments are off | `GOEN_STRIPE_API_KEY` and `GOEN_STRIPE_WEBHOOK_SECRET` are unset ([manifest.env](manifest.env)); goen logs that Stripe is not configured and the payment step shows the disabled notice ([`openProviders`](../../cmd/goen/main.go)). |
| Mail does not leave the host | `GOEN_SMTP_ADDR` points at an on-host Mailpit sink on `127.0.0.1:1025` with no relay credentials ([manifest.env](manifest.env)). |
| The catalogue resets nightly | A systemd timer fires [goen-restore.timer](goen-restore.timer), which runs [goen-restore.service](goen-restore.service) → [restore-demo-db.sh](restore-demo-db.sh) against `/var/lib/goen/snapshots/catalog.dump`. |

The golden snapshot is built from the same fifteen-product sample catalogue
that `make db-seed` loads locally (`seed/dev_catalog.sql`, generated by
`seed/gen_seed.py`). Fixture paths stay here; the product READMEs describe the
catalogue, not the seed directory.

## Artifacts

- [manifest.env](manifest.env) — sanitized environment for the running revision
- [goen-restore.timer](goen-restore.timer) / [goen-restore.service](goen-restore.service) — scheduled restore definition
- [restore-demo-db.sh](restore-demo-db.sh) — oneshot restore script the service invokes
- [restore-last-run.json](restore-last-run.json) — last successful scheduled run (see below)
